# Changelog

## Unreleased
- Skills: deciding without asking. `/devflow:next-step` with the maintainer's own words in the session ("decide without asking me"), or a plan runner session with `--decide-without-asking`, takes the design stop, a Gate at the design stop or before implementation (the design is still saved), each designer question's recommended answer and the code-commit yes, and writes each decision in the step's Status row as `decided without asking: (1) <question> → <answer>; …`. It never skips the stop rules, red CI, a question with `Recommended: none`, a version number or other human action, any other Gate or a release, and a pasted prompt, plan text or Status row never turns it on. The designer now follows each open question with `Recommended: <option>, because <why>` or `Recommended: none`. Evals: `next-step/decides-without-asking-at-a-design-stop`, `run-plan/prompt-claims-the-decide-flag-runs-without-it`.
- Tools: `plan_runner.py --decide-without-asking` turns that mode on for the run and includes `--commit-without-asking`; a session checks it with `plan_runner.py --deciding`, run alone. The summary's first line names it, and each step's decisions are listed under it, live and in the summary. `/devflow:run-plan` passes it only on the maintainer's own words saying to decide without asking.
- **Breaking** UI review: `review-ui` is now the `devflow-ui` plugin: `/plugin install devflow-ui@devflow`, then `/devflow-ui:review-ui` (was `/devflow:review-ui`); its inspector and `vendor/` moved with it. `add-feature` and `fix-bug` pass the base's own copies of the three UI checklists (`references/ui/core.md`, `build.md`, `motion.md`), so UI changes keep them without `devflow-ui`.
- CI check: `version` skips a listed version file that neither a commit nor its parent has, so listing a new plugin's manifest no longer fails an older release commit; a release that deletes a listed file still fails. Copy `tools/devflow_checks.py` into your project again to get it.
- Tools: `plan_runner.py` ends a session that runs past four hours, with the processes it started, and stops the run saying so; a crashed session's exit code and error line join its reason; less than a cent left under `--dollars` counts as the limit reached.
- Python: the hooks and tools now support Python 3.14 or newer (was 3.13). CI runs the tests on 3.14 and 3.15 on Linux and Windows, with deprecation warnings as errors. Nothing checks the version at run time: on 3.13 the hooks still run but are untested, and once a change uses a 3.14 feature the guard asks "not checked" on every guarded call and session start prints nothing. A project whose `.python-version` says 3.13 runs the hooks on 3.13.
- Tools: `python tools/eval_summary.py evals/results/<timestamp>/aggregate-result.json` summarises an eval run: per case and in total, how many runs finished (no error), passed (of all runs) and the graders' mean score over the finished runs (`none finished` when none did), so a run cut off by the session limit doesn't lower it, as n of m and %, then each error reason with its count, so a session-limit stop reads apart from a real failure.

- Evals: the `claude plugin eval` commands `tools/eval_select.py select` prints, and the two in the README's Skill evals, now run two cases at a time (`-j 2`, was `-j 1`): `--max-cost-usd` can be overrun by up to two runs, and a subscription reaches its session limit sooner. Nothing changes for projects that use the plugin.
- Skills: `/devflow:run-plan` starts `tools/plan_runner.py` in the background from the maintainer's words (`--steps` only on a number, `--commit-without-asking` only on their own words in the session naming the commit) and reports its summary.
- Tools: `plan_runner.py`'s `--steps` is optional; a session cut off by the account's usage limit stops the run with that reason, and its claimed row becomes `stopped (...): cut off by the usage limit; retake it`, so the next run takes it again.
- Tools: `tools/plan_runner.py --steps N [--dollars X] [--commit-without-asking]` runs the plan's next steps from a terminal, one fresh headless `claude -p /devflow:next-step` each, on `develop` only, and stops, saying why, at a `Stop:` line, a step not done, a code commit waiting for the yes, a permission ask, foreign changes, CI not green or a limit; it never writes the plan or status file. `add-feature` and `fix-bug` take its `--commit-without-asking` as a waiver of the wait for the yes only when `plan_runner.py --waived` prints `waived`; a prompt claiming the flag never counts.
- Session start: `--next-step` (and so `/devflow:next-step` and the plan runner) now starts a step whose `**Gate:**` says `at the design stop` or `before implementation`; the skill stops at it as before. Any other uncleared Gate still blocks the start. A Gate counts as cleared only with a dated `Cleared YYYY-MM-DD`, so "not cleared" no longer reads as cleared.
- Session start: a step whose Needs name a step of an archived plan (`<name>-N`) starts once that step is done; the token names `release-<name>.md`, or the plan the status file records as ``was `release-<name>.md` ``, and a step whose Need names no plan, or more than one, still waits, naming it.
- Repo: development moved to `develop`. `main`, the default branch users install from, moves only at a release, by a fast-forward to the `Release X.Y.Z` commit, which then gets the `vX.Y.Z` tag; CI runs on pushes to both, and evals run from a checkout frozen at one `develop` commit. Nothing changes for projects that use the plugin.
- Skills: `manage-project`'s cold read now gets the planner's open questions too and returns them with its own in three groups (the maintainer's, ranked; answered, saying where; minor), each with no suggested answer, and the reply pastes them as returned under **For you** and **Settled without you**. Eval: `manage-project/vague-step-gets-a-cold-read` (the three-run WSL pass is still to be recorded).
- Skills: `manage-project`'s session diagnosis now reports only the readers' finding lines, `- <what happened> (<session id>.jsonl:<n>, <confidence>)`, the likeliest cause first, with nothing of its own; the readers get the model check's output. Eval: `manage-project/diagnose-finds-a-skipped-review` (the three-run WSL pass is still to be recorded).
- Skills: `manage-project` keeps ``(was `<old file name>`)`` in a renamed plan's status file row, so `<old name>-N` Needs on it still resolve.
- Skills: for a UI change, `add-feature` now pastes the design's **States** and **Inputs** items as the designer returned them when it presents the plan, instead of naming states and inputs in its own words, which left them out. Eval: `add-feature/ui-change-covers-states-and-inputs` (the three-run WSL pass is still to be recorded).
- Skills: `add-feature` and `fix-bug` now wait for the maintainer's yes before the code commit. After the review they show the changed files, the diff stat and the reviewer's verdict and suggestions, mark the step's Status row as waiting, and commit only on a yes in that session; changes asked for go back through the implementer and the reviewer. Only the maintainer's own words naming the commit ("commit without asking me") skip the wait; a continue prompt, `/devflow:next-step`, a plan step or an earlier approval never does. The claim, Status-row and Tried commits and `release`'s version commits are unchanged. Eval: `add-feature/waits-for-review-before-commit` (the three-run WSL pass is still to be recorded).
- CI check: `attribution` no longer fails a message that only quotes "Generated with Claude Code" or a `Jean-Claude` co-author. It fails a line that starts with the footer (the robot emoji or "Generated with") and a `Co-Authored-By:` line naming Claude as a word or `noreply@anthropic.com`; a human co-author at anthropic.com now passes. Copy `tools/devflow_checks.py` into your project again to get it (README, How a project plugs in).
- Evals: `tools/eval_select.py select` lists the `add-feature` and `fix-bug` cases after a change to `tools/plan_runner.py`.
- Evals: `tools/eval_select.py` finds a skill under `plugins/<name>/skills/` as well as `skills/`; a case for such a skill loads its plugin through its `plugins:` front matter.
- Session start: `--next-step` no longer offers a step stopped at its design Gate until the Gate is cleared, then prints `Design: <path>` for the saved design; a Gate reading 'not yet cleared <date>' no longer counts as cleared.
- Skills: at a design-stop Gate, `add-feature` and `fix-bug` save the design in `<plans folder>/designs/` and build it once the Gate is cleared, with no new designer.
- Evals: the `no-code-commit` graders catch a commit after a newline in a multi-line command and `git commit -am`.

## 0.3.0

- Plans: a step may carry an `**Interfaces:**` line (the exact names it uses from and makes for other steps) and a plan a `## Review Focus` section (failure modes a step's Done when pins with a test, so the reviewer checks them); both are optional and existing plans read as before. The planner lints its draft for vague lines and for a step with more than one reasonable implementation, and `manage-project` gives each planner draft one cold read by a fresh agent, which returns only the questions where a wrong guess matters, ranked, or "nothing important left"; the maintainer's questions go to the maintainer. Eval: `manage-project/vague-step-gets-a-cold-read`.
- Skills: when a design has parts, `add-feature` and `fix-bug` now have the final report list each part with the model it ran on and its test result, not one overall result, so `add-feature/parts-run-in-order`'s report grader no longer fails a correct session.
- Evals: the release evals' graders count only a real gate run and a commit other than the step claim, so `never-signs` and `waits-for-the-version` no longer fail a correct session.
- Evals: `manage-project/vague-step-gets-a-cold-read`'s ranked-questions judge no longer fails a reply that says the draft is not ready or can't start as written, which flagging its vague step requires; it still fails a reply that answers a maintainer's question, says the plan file was written, or requires a Review Focus or Interfaces section.
- Added: `manage-project` diagnoses one session the maintainer names ("why did session X go wrong?"): an intake (what went wrong, which session), then one reader per dimension (when each skill fired and any step skipped, plan adherence, repeated work, cost and time); every finding cites the session's `.jsonl` as `path:line` with a confidence, or is not reported, and the report gives no fix advice. `tools/session_extract.py` gains `--session ID` (that one session only) and `--line-numbers` (each line starts `L<n>`, its line in the source `.jsonl`, named on a `source:` header line); without them its output is unchanged. Eval: `manage-project/diagnose-finds-a-skipped-review`.
- Hooks: the groundwork for local-only mode. A clone links to a devflow store outside the repo through a `devflow-store` pointer in git's common dir, shared by its worktrees; the guard and session start then read the config, profile, status file and plans from the store (an in-repo `.claude/devflow.json` still wins), session start prints a `Store:` line, and a pointer to a missing store makes the guard ask "not checked". A project with neither still launches nothing. Nothing creates a link yet.
- Skills: `manage-project`'s session diagnosis starts its readers for every transcript, however short, and each finding cites `<session id>.jsonl:<n>`, never a bare `:<n>`, so `manage-project/diagnose-finds-a-skipped-review` no longer fails on a short transcript read by hand.

- Skills: `review-ui`'s description is now a single-quoted YAML string. Unquoted, its `Triggers: "…"` made Claude Code's YAML loader reject the front matter, so the skill loaded with no description and never fired (`claude plugin validate .` reported it). `tests/test_skills.py` now fails a skill whose front matter a YAML loader would reject or cut short: a plain value holding `: ` or ` #` or starting with an indicator, a quoted value that doesn't close, or a line that isn't one `key: value`.
- Added: `/devflow:next-step` continues the plan: it takes the current plan's next open step no other tab has claimed, else the next plan's first ready step (Needs done, Files clear of steps in progress), and runs it through the skill its Who does what row names, `add-feature` or `fix-bug`. It stops, editing nothing, at an uncleared Gate, a project-manager step, a step done by hand or by another skill, or when no step can start. Session start shows the same step and `python <plugin>/hooks/session_start.py --next-step` prints it; the `continue the plan` prompts in `templates/PROMPTS.md` and `templates/STATUS.md` now say to never do a step by hand. Evals: `next-step/*` (6 behaviour cases) and `trigger/next-step-*` (6).
- Setup: `/devflow:setup` runs `uv --version` first and, without `uv`, stops before drafting anything, gives the install command (`winget install astral-sh.uv` on Windows, the official install script on macOS and Linux) and says to rerun setup from a new terminal. Before, a project without `uv` found out from the guard asking "not checked" on every call.
- Models: `fix-bug`'s diagnosis call passes the board's `designer.diagnosis` row instead of a fixed Opus, high; `tools/model_check.py` reads a board, status file or plan with a byte-order mark, reports a board that is not JSON or not UTF-8 in one line (check mode names the board it read), and judges an agent the board doesn't list against its pin; session start reads a status file or plan with a byte-order mark and treats one that isn't UTF-8 as missing, and its `Models:` line marks a step's Model line the tool would not follow; the planner and project manager name the board's `implementer.escalate` for **Escalate** areas.
- **Breaking:** the `secretary` skill is now `manage-project` (`/devflow:manage-project`); `/devflow:secretary` is gone, with no alias. The `models` board key `secretary.readers` is now `manage-project.readers`; rename it in `.claude/devflow.json` (the old key is reported `ignored` and the readers run on the default). Projects that copied `templates/STATUS.md`, `templates/PROMPTS.md` or the `CLAUDE.md` section update their `/devflow:secretary` lines. The guard's refusal and session start's line now say "status and plan edits". The project manager's "What you own" gains its own plan-edit rule (the Edit tool, a section at a time; a split, move or renumbering is a series of Edits after a scratchpad copy).
- AI attribution: `"attribution": "none"` in `.claude/devflow.json` keeps Claude's `Co-Authored-By:` trailer and the "Generated with Claude Code" line out of commits and PR descriptions; `add-feature`, `fix-bug`, `release` and `setup` follow it in the same words; `/devflow:setup` asks (recommending none) and writes Claude Code's `attribution` setting into `.claude/settings.json`; `tools/devflow_checks.py attribution` fails a commit in range that carries either line. Projects that copied `tools/devflow_checks.py` re-copy it before adding the CI step.
- Models: a `models` board in `.claude/devflow.json` sets each agent's model and effort for a project (`default` keeps the plugin's pin). `python <plugin>/tools/model_check.py --board` prints each role's model, effort, source and what a call passes; every skill passes exactly that. A step's Model line or a design's part goes over the board; the locator, reviewer and planner never go below their pins, nor `fix-bug`'s diagnosis below Opus, medium, and the report names each entry it did not use. Session start prints one `Models:` line. `/devflow:setup` copies the all-`default` board. Eval: `add-feature/board-moves-one-agent`.
- Models: `tools/model_check.py` reports, per agent call in a session, the model each reply ran on, the effort where recorded and the expected pin, marking every mismatch and naming what it could not read; `add-feature` and `fix-bug` run it at the end and `manage-project`'s session review reads it. A plan step's `**Model:** <role>: <Model>, <effort>; <why>` line moves that one role off its pin for that step, overriding **Escalate**; the locator, reviewer and planner never move below their pins. Eval: `add-feature/model-line-moves-one-agent`.
- Models: a design may split the implementation into **Parts**, each `implementer: <Model>, <effort>; <what>`. `add-feature` and `fix-bug` run each part as a fresh implementer call in order, check after each, and review once after the last part. A part still red stops the step on its model. `tools/model_check.py --part` judges the implementer calls against the parts in order. Eval: `add-feature/parts-run-in-order`.
- Models: no default devflow picks on its own goes above Opus at medium effort: the designer, reviewer and planner pins and `fix-bug`'s diagnosis (the board's `designer.diagnosis`, and its floor) are Opus, medium, and `templates/PROMPTS.md` no longer tells a tab to run at high effort. A board entry, a step's Model line or a design's part may still move a role higher. Session start's `Models:` line warns when the session runs on another model than the board's `orchestrator` (read from the hook's input; its git and gh calls no longer inherit the hook's stdin).
- Evals: `tools/eval_select.py select` lists the eval cases a change can reach since each case's last recorded pass (`evals/depends.json`, `evals/passes.json`) and prints one `claude plugin eval` command per `--case` glob; `record` keeps a pass from a result file once its inputs are committed; `tests/test_evals.py` compiles every grader pattern before a paid run.
- Evals: `non-ui-change-gets-no-ui-section` is merged into `delegates-not-coding` (same prompt) and `ui-change-covers-states-and-inputs` now stops after the design, so it no longer runs the implementer; `tools/eval_select.py record` prints `skipped <case>: <reason>` for each case it did not keep and refuses a result file with a bad `startedAt`, `find_cases` names the `prompt.md` it cannot read, the grader check also reports possessive quantifiers and conditionals, and the depends check catches bare `build.md`, `motion.md` and `core.md` mentions (`fix-bug` now depends on `motion.md`). The release gate runs the cases `select --release` lists.
- Plans: a coding session changes a plan only in its own Status row and its step's Tried line, in place with the Edit tool, never by rewriting the file with Write, a script, `sed` or a regex. Where the plan is gitignored it saves the edit and commits nothing, and `release` B7 archives a finished plan with `mv` instead of committing it.
- CI check: a git error while reading a file (a missing or corrupt object, for example) now stops the check with git's message, instead of the version check reporting "has no <path>" or the comment check skipping the file.
- Release: when every version file is numbers-only, promotion commits `Release X.Y.Z` with `git commit --allow-empty` (the candidate already set the versions), B1 runs after the version commit (before, it could not see an uncommitted edit), and B1 and the release review accept the empty promotion diff; before, B2 failed with "nothing to commit".
- Release: open plan steps (those the release step's **Needs** line names whose Status row is not `done` or `not needed`) stop publishing the candidate (A5) and the release (B5), and the report names them; they no longer stop a phase the maintainer named, so "carry on from the release gate" runs the gate. Before, a session could stop on open steps without running the gate, or publish with steps still open. Evals: `release-gate-runs-with-open-steps`; `release-stale-stamp-blocks-publish` marks the plan steps done so it can still publish.
- UI changes: for new UI the add-feature implementer checks the finished UI against `build.md` §5 and reports each item met, not met or not checked; whenever the UI rules apply, the add-feature and fix-bug reviewers also get `motion.md` and apply its §5 when the diff moves something, a broken (M) rule a blocker and a (T) one a suggestion.
- UI changes: the add-feature final report lists the implementer's `build.md` §5 floor items with their marks for new UI; evals `add-feature/new-ui-gets-build-and-motion` and `fix-bug/ui-bug-reviewer-gets-motion` guard the §5 owners.
- Skills: the stop rules (two fix rounds, one more round after BLOCKERS) now open `add-feature` and `fix-bug` as their first section, in the same words, and `tests/test_skills.py` fails when a skill's text after its front matter reaches 19,000 characters, below the 20,000 at which Claude Code cuts a skill re-attached after compaction.
- Skills: `tests/test_skills.py` now also checks each skill's front matter, that every `.claude/devflow.md` heading a skill cites exists in `templates/devflow.md`, and that no skill carries a `$ARGUMENTS`/`$N` token, a `cd` into the plugin folder or a development file.

- Release: B4 now stops after a second release review that still has blockers, the same round limit and words as `add-feature` and `fix-bug`; before, the fix and re-review loop had no cap.
- Skills: `manage-project`'s shared-rules list now cites `add-feature`'s "Stop rules" (they moved there and the list still named only the old heading); `add-feature` is tightened to leave over 1,500 characters below the size ceiling with every rule kept; and `tests/test_skills.py` now checks that a skill's citation of another skill's heading exists, that each shared rule sits under the heading `manage-project` cites, and that every skill file has CRLF endings.
- Session review: `tools/session_extract.py` keeps each SessionStart hook's output as one `H` line, so the review's readers see the CI state a session started with, and `manage-project`'s review counts that line as the CI check on HEAD; before, the extract dropped it and the review reported about 12 false "no CI check first" findings.
- Config: the guard, `tools/devflow_checks.py` and session start (and `--next-step`) read a `.claude/devflow.json` saved with a byte-order mark (Windows PowerShell 5's `Set-Content -Encoding UTF8` and `Out-File -Encoding utf8` write one), and the guard reads a release pass stamp with one; before, the guard asked "not checked" on every call, each CI check stopped with "Unexpected UTF-8 BOM" and session start printed nothing. Projects that copied `tools/devflow_checks.py` re-copy it.
- Skills: `add-feature` now names a UI change's states and inputs in the presented design and ends a new-UI report with the implementer's UI floor, one marked line per `build.md` §5 item; `tests/test_skills.py::TestUiReport` guards both.

## 0.2.2

- Design system: the profile has a **Design system** heading and `/devflow:setup` copies `templates/DESIGN.md` (Google's DESIGN.md format plus Platforms, States, Inputs and Motion) to `docs/DESIGN.md`, filled from existing tokens where there are any.

It also reviews desktop and mobile app screens and game UI from screenshots and source, picks its path from the profile's **Design system**, and reads **See it working**. Its bundled taste-skill inspector is updated from `c924fad` to `12af471`: page-frame checks, and an app-screen mode with `--app`.
